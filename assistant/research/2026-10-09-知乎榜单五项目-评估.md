# 榜单五项目评估（知乎 · 2026-10-09）

> 来源：用户转知乎作者"深杯酒满"的 GitHub Trending 榜单点评，要求评估。
> 结论先行：**两个老朋友（openhuman / agentmemory）保持设计参照并新增吸收点；两个新面孔（CloakBrowser / AiToEarn）记档不接；mattpocock/skills 维持素材库定位、记一个通用模式。** registry 无新增（无一进入集成/提案——按四铁律，参考档案不登记）。

## 1. tinyhumansai/openhuman —— v2 主参照，新增两个吸收点

**是什么**：私人 AI 超级智能体（本地优先、模块化、引擎全可插拔：LLM 26 家 BYOK / embeddings / memory / web search 各自可换）。

**原有定位**（AGENTS.md 蓝图 v2 / HANDOFF 六）：118 个 OAuth 同步个人上下文；通道抽象参照（邮件=通道之一）。

**本次新增吸收**：
- **Web search 三能力角色**：search（找链接）/ answer（直接答）/ page contents（取正文），10 个提供商按角色归类——v1 第二批做搜索工具时的抽象模板（我们现在只有智谱 web_search 开关）。
- **Memory v2 = Recall/Fetch/Store + 可插拔引擎**：与我们的 retain/recall（+第二批 reflect）命名互相印证，接口先行、引擎可换。
- 引擎全插件化与我们 sources/channels 的路线同构，佐证方向。

## 2. rohitg00/agentmemory —— v1 记忆层参照，拿到关键实测数字

**是什么**：编码 agent 的持久记忆（MCP 工具 memory_recall / memory_smart_search 等）。

**已有吸收**（HANDOFF 六）：四层分类 + hindsight retain/recall/reflect 命名。

**本次新增吸收**：
- **自家基准给了 BM25 的底气**：BM25-only fallback 在 LongMemEval 上 86.2% / 94.6% / 71.5%——HANDOFF 定的"BM25 起步不上向量库"从此有实测背书，第二批放心先 BM25。
- **演进路线确认**：BM25 → 本地向量（EMBEDDING_PROVIDER=local，MiniLM 端上推理，无 API 依赖）→ 图谱 RRF 融合，按需逐级上，每级都保留 keyless 可用。
- 评测方法可抄：adapter-pluggable 评测架 + 公开 500 题集——第二批记忆升级时自建小评测照此办理。

## 3. CloakHQ/CloakBrowser —— 记档不接 ❌

**是什么**：隐身 Chromium，Playwright/Puppeteer 直接替换；过 Cloudflare Turnstile / FingerprintJS / reCAPTCHA v3（0.9 分）；`humanize=True` 行为模拟；pip/npm 安装，免费档 + Pro 授权。

**为什么不接**：我们的数据源全是公开温和页面（GitHub trending、微博官方接口、60s 博客），没有反爬对抗需求；绕过 bot 检测与平台 ToS 存在合规灰色地带，与项目"只抓公开数据"的路线相悖；Chromium 二进制 + 授权体系也违反轻量底线。

**重议条件**：无。真遇到强反爬源，正解是换源（同 tohub 微博榜失效后换官方接口的做法），不是隐身。

## 4. mattpocock/skills —— 维持"素材库按需取用"，记一个通用模式 📌

**是什么**：给编码 agent 的生产级技能包（engineering + productivity 两类：grill-me / to-spec / prd-to-plan / qa / git-guardrails / design-an-interface 等，SKILL.md 标准格式）。

**对**：编码域不转化——我们的 agent 不写代码，写代码是 ZCode 的活；10-09 早报的定位（"收件箱处理变复杂后挑着用"）维持不变。

**可吸收的通用模式一条**：**grill-me（动手前先盘问）**——执行非平凡任务前，agent 先把歧义点列成问题向用户逐条确认，答完再动手。与系统提示"缺信息直接问"同源，但它给了可操作的仪式；v1 第二批改 daemon 提示词时可并入。

## 5. yikart/AiToEarn —— 参考档案，条件触发 📌

**是什么**：OPC（一人公司）的 AI 内容营销平台：多平台内容生成/分发/互动/变现，含 MCP 支持（2026-03 起）、内容交易市场、线下商户方案；开源 + 托管服务的赞助驱动模式。

**对**：这不是助手基建，是"用助手赚钱"的业务层——接不接取决于你是否做内容变现，是业务决定不是技术决定。

**可吸收**：MCP 支持再次出现（与 10-09 早报 rea 同向）——**MCP 正成为 agent 工具挂载的事实标准**，v1 daemon 第二批加 MCP 客户端支持的理由又多一条。

**重议条件**：你想做内容变现，且 v1 daemon 已支持 MCP。
