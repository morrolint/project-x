# 个人助手 · 使用手册

一个常驻在你 Mac mini 上的个人助手：Telegram 随时说话，桌面控制台看全景，早晚班自动汇报。
所有文件都在本机，不上传任何服务器。运行者是 `agent/` 里的 daemon（launchd 常驻）——本手册教你怎么使唤它。

## 两个入口

| 入口 | 适合 | 地址 |
|---|---|---|
| **Telegram** @m0rro_bot | 随时随地，手机优先 | 直接发消息（白名单只认你） |
| **桌面控制台** | 坐在电脑前，看长内容 | http://127.0.0.1:8787 |

两个入口共用同一个记忆、同一套工具、同一个确认门。控制台还能看：今日早报全文、任务线五态、收件箱、今日 token 消耗。

## 日常怎么说

- **交代任务**："30 分钟后提醒我收衣服"“以后每天帮我看 X"“把这个记进收件箱：……"
- **查东西**："看下最近的 GitHub 什么火"（日/周/月榜都能要）“为什么我们的通道选 Telegram"（它会去查自己的决策记录 ADR-001）
- **要报告**："生成今天的早报"——生成后自动推送到 Telegram，完整版在 `reports/`
- **让它出图**："把月榜画成图发我"——编辑级 SVG→PNG 图表
- **确认门**：它要写文件时会先发预览，Telegram 里点按钮、控制台里回复「确认」才真正执行；回复其他内容则取消并按新指令处理

## 班次（自动，无需过问）

| 班次 | 时间 | 干什么 |
|---|---|---|
| 早班 | 每天 08:00 | 生成早报（要闻 + GitHub Trending 逐项目深读 + 科技动态 + AI 点评）→ 推送 Telegram → 处理收件箱 → 发班次汇报 |
| 晚班 | 每天 21:00 | 晚间简报（与早报对比 Trending ↑↓）→ 白天动态 → 收件箱巡检 → 推送 |
| 记忆固化 | 周日 22:00 | 归并当月记忆为 observations（带证据计数，求精不覆盖） |
| 主动扫描 | 每 3 小时 | Trending 出现高热新面孔时主动推送 |

由 daemon 内置调度器执行（ADR-004），机器睡眠期间错过的消息由 Telegram 服务端保留、唤醒补收。

## 收件箱

`TASKS.md` 待办区一行一条，写清"要什么"即可。两个入口都会处理它：早班自动化（每日）与你的 Telegram 对话（即时）。完成的移入"已完成"区留痕。

## 能力清单（13 工具）

收件箱查/加/完成 · 生成早报/晚间简报 · GitHub Trending（日/周/月）· 读写文件（分级确认）· 列目录 · 设提醒 · 活动查询（token 消耗/工具统计）· 记忆存/查 · **知识库检索**（它自己的架构/决策/调研档案）· 出图

## 边界（诚实版）

- ⚠️ 机器睡眠/断网期间 Telegram 不可达（消息由服务端保留，恢复补收）；台式机建议 `pmset -c sleep 0`
- ⛔ `docs/` 敏感文件与一切密钥：任何口径不读取、不入上下文、不入仓库（代码层强制，非提示词约定）
- ⛔ 不私自安装任何第三方依赖；新集成走 `integrations/` 提案 + 你批准
- ⚠️ 语音/图片消息暂不处理（v1 只认文本）

## 隐私

`docs/`（证件等）永不进对话上下文；`.secrets.env` 凭据永不读取复述；记忆与日志全在本机；
发给 LLM 的只有当轮所需切片。细节见 [ARCHITECTURE.md](ARCHITECTURE.md) 不变量 1。
