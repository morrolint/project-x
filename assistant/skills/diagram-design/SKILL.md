## 方法

1. **先判断该不该画**：只有"读者从图里学到的东西多于一段好文字/表格"时才画。列表用列表；属性对比用表格（拓扑变化才用架构变更图）；一个框的"图"直接写句子。
2. **选型两步走**：当行为/状态/权限/风险承载语义时，先选**语义模式**（扇入瓶颈、生命周期阶段图、信任边界、治理控制目录……），再选承载它的视觉类型；无行为语义就直接选类型。常用映射：
   - 组件+连接 → 架构图；结构前后对比 → 架构变更图（带变更清单）
   - 分支决策 → 流程图；参与者间时序消息 → 时序图；状态+迁移+守卫 → 状态机
   - 实体+字段+关系 → ER 图；跨职能交接 → 泳道图；任务/阶段 → 甘特图
   - 双轴定位/优先级 → 象限图；多实体多维评分 → 雷达图；强化循环 → 循环图
   - 层级包含 → 嵌套图；父子关系 → 树图；抽象层堆叠 → 分层图
   - 整体→分项桥接（预算桥） → 瀑布图；流向流量 → 桑基图；归因分解 → 鱼骨图；演化地图 → Wardley 地图
3. **设计哲学：删除是最好的质量动作**。
   - 每个节点代表一个独立想法——总是同时出现的两个节点合并为一个；
   - 每条连线都携带信息——布局已能表达的关系，删掉线；
   - 焦点色（accent）是编辑手段不是旗标：一张图最多 1–2 个焦点节点；
   - 目标密度 4/10：超过 9 个节点大概率该拆成两张图；
   - 图不是"加完了"就完成，是"没有东西可删"才完成。
4. **技术形态**：产出**自包含 HTML + 内联 SVG**（可直接打开/嵌入，不依赖 Mermaid/draw.io 渲染器）；设计 token 用语义角色（paper/ink/muted/accent，亮暗两套），不硬编码 hex；可从 Mermaid/draw.io/.excalidraw 源**重绘**成体面版本——收到烂 Mermaid 图时这是标准动作。
5. **动效克制**：默认静态；只有表达有序变化且确实更清楚时才加动画。

## 注意

- 画之前自问："读者从图里学到的是否多于一段好文字？"——不是就不画。
- 本技能是**方法论提炼**，不含上游的 44 类完整参考与 style guide；需要某类型的具体布局规范（如甘特/桑基的网格与标注约定）时，按 MIT 许可抓上游对应 `references/type-*.md`（见来源），用完即走，不必入库。
